<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| prompt files → OpenAI API | Prompt content is sent as system message to OpenAI — no user input touches prompt files |
| OpenAI response → DB | Raw JSON parsed and stored; openai-client.ts does not validate field values, only parses JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | server/prompts/v2/*.txt | accept | Prompt files are server-side only, not user-accessible. No RLS needed. File integrity relies on standard OS permissions. |
| T-11-02 | Information Disclosure | AnalysisSummary.desglose_riesgo | mitigate | Field is derived from AI-generated contract analysis, not user PII. No mitigation needed beyond existing RLS on analyses table. Confirmed: RLS already enforced per CLAUDE.md. |
| T-11-03 | Tampering | Hallazgo.categoria_riesgo enum | accept | LLM may emit values outside the controlled enum. Phase 12 UI should treat unknown values as "Otro" — defensive rendering, not a security issue. Low severity. |
</threat_model>
