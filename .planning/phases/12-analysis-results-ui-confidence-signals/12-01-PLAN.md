## Executor notes (apply to every task)

- **Docker only.** Run every npm/npx command inside the container: `docker compose exec app <cmd>` (CLAUDE.md). If `docker compose ps` does not list `app` as running, start the stack with `docker compose up -d` first.
- **Tailwind does not scan `composables/`.** `tailwind.config.js` content globs cover `components/`, `layouts/`, `pages/`, `plugins/`, `app.vue` only. Every Tailwind class string must live literally in a `.vue` file; composables return semantic values (labels, levels, ids) only, never class names.
- **No Nuxt auto-imports under vitest.** The unit project uses plain `@vitejs/plugin-vue` + happy-dom. Every new or modified SFC must import `ref`/`computed` from `"vue"` explicitly and import child components by path (RiskCard.vue already follows this; AnalysisStatusBadge.vue does not, so do not copy its script imports).
- **Lint rules that bite:** `@typescript-eslint/consistent-type-definitions: interface` (object shapes are `interface`, not `type`); prettier runs as an ESLint error, so run `docker compose exec app npx eslint --fix <files>` before the lint gate.
- **tsconfig is strict** (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noUnusedLocals`). Optional props follow RiskCard's `?: T | undefined` convention. `tsc --noEmit` has pre-existing errors in `server/api/admin/` (Phase 11 SUMMARY), so type gates filter by file.
- **Weights:** new elements use only 400 (default) and 900 (`font-black`) per UI-SPEC Typography. **Accent:** the Nuxt Green token is reserved for breakdown bars, the coverage value and the existing detail link; nothing new in this plan uses it.
- **Rendering AI text:** titulo, explicacion, cita_textual, clausula, riesgo_real, mitigacion and confianza originate from model output shaped by an uploaded (untrusted) contract. Render all of it through mustache interpolation only; never through a raw-HTML directive or innerHTML.
