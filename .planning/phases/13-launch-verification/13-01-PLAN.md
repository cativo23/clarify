<objective>
Fix the repository side of the first production deploy and prove it end-to-end locally before any release is cut. This covers D-01 (the deploy step is in scope) and prepares the release that D-02 cuts in plan 13-03.

Purpose: This plan leads the phase with the tracer. The tracer is the single container path production will run: the CI-built image, started from docker-compose.prod.yml, with its runtime env, answering /api/health through Redis. Planning found three deploy blockers in addition to RESEARCH P4 (the placeholder host). Each was confirmed against the host or the code:
1. The polaris2 Traefik (v3.6) defines entrypoints `web`/`websecure` and resolver `letsencryptresolver`. The compose labels use names that do not exist there, so the router would never attach.
2. The app and worker services have only a `build:` block. The deploy job copies nothing to the server except the compose file, so `docker compose pull` has nothing to pull and `up -d` would try to build without a Dockerfile.
3. The image is built in CI without env, so the nuxt.config.ts `process.env` defaults are frozen at build time (redisHost "localhost", openaiApiKey ""). Nuxt only overrides runtimeConfig at runtime through `NUXT_`-prefixed variables, so the plain names in the compose file are ignored by every `useRuntimeConfig` consumer. This affects Redis, OpenAI, admin email and Stripe.
Any compose change after the tag costs another alpha release. That is why the local RED/GREEN proof happens here, before release.

Output: edited docker-compose.prod.yml (tracer), a CHANGELOG `[1.0.0-alpha.20]` section, package.json version bump, and a corrected DEPLOY.md.
</objective>
