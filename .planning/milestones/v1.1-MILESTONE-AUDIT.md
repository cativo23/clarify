## Cross-Phase Integration

### BLOCKER — ADMIN-04: Suspension flag never enforced

`server/api/admin/users/[id].patch.ts` writes `is_suspended=true`, but `grep -r "is_suspended"` returns zero readers in the upload, auth, or worker paths. A suspended user retains full platform access. Cross-phase wiring (Phase 6 → Phases 2/3) is missing.

### BLOCKER — DEPLOY-01: `.env.example` incomplete

Server code references env vars not in the template:
- `ADMIN_EMAIL` — `nuxt.config.ts:81` + `server/utils/auth.ts` admin gating. Without it, **no admin can log in to the dashboards built in Phase 6**.
- `STRIPE_PRICE_ID_5_CREDITS`, `..._10_CREDITS`, `..._25_CREDITS` — `server/utils/stripe-client.ts:20-39` falls back to hard-coded test price IDs, which would silently bill the wrong product in production.
- `ALLOWED_REDIRECT_ORIGINS`, `DISABLE_WORKER`, `NODE_ENV` — referenced in server code, undocumented.

### WARNING — ADMIN-01: Funnel Stage 2 RPC missing

`funnel.get.ts:75-101` calls RPC `get_email_verified_users_in_range`, which does not exist in any `database/migrations/*.sql` file. The fallback branch returns the Stage 1 query, so "Email Verified" always equals "Signups" and the displayed retention is misleadingly 100%.

### WARNING — ADMIN-02: Package inference brittle

`revenue.get.ts:144-153` infers package tier from hard-coded price bands ($4.49–5.49 → "5 credits", etc.) instead of joining on `credits_purchased` or a package id. Future price changes in `stripe-client.ts` silently break the breakdown.

## Broken Flows

- **Admin login (fresh prod deploy):** No `ADMIN_EMAIL` in `.env.example` → no admin gate set → admin dashboards inaccessible.
- **Suspend user:** UI shows "Suspended", but suspended user can still upload, queue analyses, and consume credits.
